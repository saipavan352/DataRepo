🎯 Locators — Finding Elements The most important skill — if your locator breaks, your test breaks
💡
Quick rule: Always prefer id, then name, then CSS selector. Use XPath only when CSS can't reach it (e.g., find by text, parent/sibling navigation). Absolute XPath /html/body/div[1]/... — never use in real tests.
All 8 Locator StrategiesBy.*
findElement() returns first match and throws if not found. findElements() returns a List (empty list if none found — no exception).
// ── Single element ──
WebElement el = driver.findElement(By.id("username"));
WebElement el = driver.findElement(By.name("email"));
WebElement el = driver.findElement(By.className("btn"));
WebElement el = driver.findElement(By.tagName("h1"));
WebElement el = driver.findElement(By.linkText("Sign In"));
WebElement el = driver.findElement(By.partialLinkText("Sign"));
WebElement el = driver.findElement(By.cssSelector("#form .btn"));
WebElement el = driver.findElement(By.xpath("//button[@type='submit']"));

// ── Multiple elements ──
List<WebElement> rows = driver.findElements(By.cssSelector("table tr"));
int count = rows.size();

// ── Find within element (scoped) ──
WebElement form = driver.findElement(By.id("loginForm"));
WebElement btn  = form.findElement(By.tagName("button"));
Locator Priorityuse this order
1
Use By.id()
Unique, fast, never changes
2
Use By.name()
Good for form fields
3
Use By.cssSelector()
Fast, readable, flexible
4
Use By.xpath()
When CSS can't do it
✗
Avoid absolute XPath
Breaks on any HTML change
Check if element exists (no exception)safe check
Use findElements to check existence — returns empty list instead of throwing.
List<WebElement> els = driver
    .findElements(By.id("banner"));
boolean exists = !els.isEmpty();
boolean shown  = exists &&
    els.get(0).isDisplayed();
CSS Selector PatternscssSelector
Use CSS for most cases — faster than XPath and easier to read.
"#loginBtn"             // id
".primary-btn"          // class
"button.primary"       // tag + class
"div#main .card"       // nested
"div > p"              // direct child only
"input[type='email']"  // attribute match
"a[href*='login']"     // href contains
"input[name^='user']"  // name starts with
"input[name$='name']"  // name ends with
"li:nth-child(3)"      // 3rd list item
"li:first-child"       // first
"li:last-child"        // last
"input:not([disabled])" // not disabled
"label + input"        // sibling after label
XPath Patternsxpath — when CSS can't
Use XPath when you need: find by text, go to parent, or traverse siblings.
// by text content
"//button[text()='Login']"
"//button[contains(text(),'Log')]"
"//span[normalize-space()='Submit']"

// by attribute
"//input[@placeholder='Email']"
"//input[contains(@class,'active')]"
"//input[starts-with(@id,'user')]"

// parent / ancestor
"//td[text()='Alice']/.."       // parent tr
"//td[text()='Alice']/../td[2]" // sibling td

// following/preceding sibling
"//label[text()='Name']/following-sibling::input"
"//label[text()='Name']/preceding-sibling::div"

// index (1-based in XPath!)
"(//table//tr)[3]"

// AND / OR
"//input[@type='text' and @name='q']"

⏳ Waits — Synchronization The #1 cause of flaky tests is wrong or missing waits
🚫
Never use Thread.sleep(ms) — it always waits the full time even if the element appears early. It makes tests slow AND fragile. Use Explicit Wait instead.
⚠️
Don't mix Implicit + Explicit Wait — they interact unpredictably. Pick one strategy per project. Explicit Wait is preferred.
Implicit Waitglobal / simple projects
Set once in @BeforeMethod. Tells WebDriver to poll the DOM for up to N seconds on every findElement call before throwing. Good for simple scripts, risky in complex frameworks.
// Set ONCE after creating driver
driver.manage().timeouts()
      .implicitlyWait(Duration.ofSeconds(10));

// Now every findElement auto-waits up to 10s
WebElement el = driver.findElement(By.id("btn"));
Explicit Wait — WebDriverWait✅ preferred
Use when a specific element or condition needs to be waited for — dynamic content, AJAX, page transitions. More precise than implicit wait.
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(15));

// Wait for element to be visible
WebElement el = wait.until(
    ExpectedConditions.visibilityOfElementLocated(
        By.id("result")));

// Wait for element to be clickable
wait.until(ExpectedConditions
    .elementToBeClickable(By.id("submitBtn")))
    .click();

// Wait for element in DOM (not necessarily visible)
wait.until(ExpectedConditions
    .presenceOfElementLocated(By.id("msg")));

// Wait for element to disappear (loader/spinner)
wait.until(ExpectedConditions
    .invisibilityOfElementLocated(By.id("loader")));
All ExpectedConditions — Quick ReferenceEC.*
Use these as arguments to wait.until(). Pick the right condition for the situation.
// ── Visibility ──
.visibilityOfElementLocated(by)    // element visible
.visibilityOf(webElement)          // same, WebElement ref
.invisibilityOfElementLocated(by)  // spinner gone
.invisibilityOf(webElement)

// ── Presence (in DOM, may be hidden) ──
.presenceOfElementLocated(by)
.presenceOfAllElementsLocatedBy(by)

// ── Clickability ──
.elementToBeClickable(by)
.elementToBeClickable(webElement)

// ── Text / attribute ──
.textToBePresentInElement(el, "text")
.textToBePresentInElementLocated(by, "text")
.textToBePresentInElementValue(el, "val")
.attributeContains(el, "class", "active")
.attributeToBe(el, "value", "done")

// ── URL ──
.urlContains("dashboard")
.urlToBe("https://site.com/home")

// ── Title ──
.titleContains("Home")
.titleIs("Dashboard - App")

// ── Selection (checkbox) ──
.elementToBeSelected(el)
.elementSelectionStateToBe(el, true)

// ── Alert ──
.alertIsPresent()

// ── Frame ──
.frameToBeAvailableAndSwitchToIt(by)

// ── Count ──
.numberOfElementsToBe(by, 5)
.numberOfElementsToBeMoreThan(by, 0)

// ── Custom lambda ──
wait.until(d ->
    d.findElement(By.id("badge"))
     .getAttribute("class")
     .contains("active"));
FluentWaitadvanced
Use when polling frequency matters — e.g., checking every 500ms for a slow AJAX response, and you want to silently ignore NoSuchElementException during the wait.
Wait<WebDriver> fw = new FluentWait<>(driver)
    .withTimeout(Duration.ofSeconds(30))
    .pollingEvery(Duration.ofMillis(500))
    .ignoring(NoSuchElementException.class)
    .ignoring(StaleElementReferenceException.class)
    .withMessage("Element did not appear!");

WebElement el = fw.until(d ->
    d.findElement(By.id("dynamicEl")));
Timeoutsdriver config
Set page load timeout to prevent tests hanging on slow pages. Script timeout matters when running async JS via JavascriptExecutor.
// Max time to wait for page to load
driver.manage().timeouts()
    .pageLoadTimeout(Duration.ofSeconds(30));

// Max time for executeAsyncScript
driver.manage().timeouts()
    .scriptTimeout(Duration.ofSeconds(10));
🪟 Windows & Tabs When clicking opens a new tab/window, or you need to open one manually
Switch to New Tab / WindowswitchTo
After clicking a link that opens in a new tab — grab the parent handle first, then loop handles to find and switch to the new one. Switch back to parent when done.
// 1. Store parent handle BEFORE clicking
String parent = driver.getWindowHandle();

// 2. Action that opens new tab
driver.findElement(By.id("newTabLink")).click();

// 3. Wait for new window to appear
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(5));
wait.until(d -> d.getWindowHandles().size() > 1);

// 4. Switch to new tab
for (String h : driver.getWindowHandles()) {
    if (!h.equals(parent)) {
        driver.switchTo().window(h);
        break;
    }
}
// 5. Work on new tab...

// 6. Close new tab, return to parent
driver.close();
driver.switchTo().window(parent);
Open New Tab / Window (Selenium 4)Selenium 4 only
Use this cleaner Selenium 4 API to open and switch to a new tab or window without looping through handles.
// Open new TAB and switch to it
driver.switchTo().newWindow(WindowType.TAB);
driver.get("https://example.com");

// Open new BROWSER WINDOW and switch
driver.switchTo().newWindow(WindowType.WINDOW);
driver.get("https://example.com");

// All handles
Set<String> allHandles = driver.getWindowHandles();
String current = driver.getWindowHandle();
🖼️ iFrames When elements are inside an <iframe> — findElement will fail until you switch in
⚠️
Cannot find elements inside an iframe without switching first. If findElement fails and you see <iframe> in the HTML, you need to switch into it first.
Switch Into & Out of iFrameswitchTo
After switching in, all findElement calls search only inside that frame. Always switch back to defaultContent() when done, or nested frame work will fail.
// Switch by index (0 = first frame)
driver.switchTo().frame(0);

// Switch by name or id attribute
driver.switchTo().frame("iframeName");

// Switch by WebElement (most reliable)
WebElement iframe = driver.findElement(
    By.tagName("iframe"));
driver.switchTo().frame(iframe);

// ── Now interact inside the frame ──
driver.findElement(By.id("elementInsideFrame")).click();

// ── Return to main page ──
driver.switchTo().defaultContent();

// ── Go up one level (nested frames) ──
driver.switchTo().parentFrame();
Wait + Switch Patternbest practice
Wait for the iframe to load before switching. This is the correct production pattern.
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(10));

// Wait for frame AND switch in one step
wait.until(ExpectedConditions
    .frameToBeAvailableAndSwitchToIt(
        By.id("paymentFrame")));

// Now inside frame — interact normally
driver.findElement(By.id("cardNumber"))
      .sendKeys("4111111111111111");

// Back to main page
driver.switchTo().defaultContent();
🔔 Alerts, Confirms & Prompts JavaScript browser popup dialogs — cannot interact with them via findElement
Handle All 3 Alert TypesswitchTo().alert()
Alert = OK only. Confirm = OK + Cancel. Prompt = OK + Cancel + text input. All handled the same way — just add sendKeys() for prompt.
// ── Wait for alert then switch ──
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(5));
wait.until(ExpectedConditions.alertIsPresent());

Alert alert = driver.switchTo().alert();

alert.getText();           // read alert message
alert.accept();           // click OK
alert.dismiss();          // click Cancel
alert.sendKeys("input"); // type in prompt

// ── Prompt full flow ──
wait.until(ExpectedConditions.alertIsPresent());
Alert prompt = driver.switchTo().alert();
prompt.sendKeys("My Answer");
prompt.accept();
Alert vs Confirm vs Prompttypes
Know which type is on screen so you call the right method.
TypeTrigger JSButtonsAction
alert()alert("msg")OK onlyaccept()
confirm()confirm("?")OK / Cancelaccept() or dismiss()
prompt()prompt("?")OK / Cancel + inputsendKeys() then accept()
🖱️ Actions Class For mouse gestures and keyboard combos that normal click/sendKeys can't do
Mouse ActionsActions
Hover to reveal tooltips or dropdown menus. Right-click for context menus. Drag-and-drop for sortable lists or file drop zones. Always end with .perform().
Actions actions = new Actions(driver);

// ── Hover (triggers dropdown menus) ──
actions.moveToElement(menuItem).perform();

// ── Double click ──
actions.doubleClick(element).perform();

// ── Right-click (context menu) ──
actions.contextClick(element).perform();

// ── Drag and Drop ──
actions.dragAndDrop(source, target).perform();

// ── Drag by pixel offset ──
actions.dragAndDropBy(element, 100, 0).perform();

// ── Click and hold → move → release ──
actions.clickAndHold(source)
       .moveToElement(target)
       .release().perform();

// ── Move to offset from element center ──
actions.moveToElement(el, 10, 20).perform();

// ── Click at specific coordinates ──
actions.moveToElement(el).click().perform();
Keyboard Actions & ScrollActions
Use keyDown/keyUp for Ctrl+Click multi-select, Shift+Click range select. Use scrollToElement when an element is off-screen and clicking fails.
Actions actions = new Actions(driver);

// ── Ctrl+Click multiple items ──
actions.keyDown(Keys.CONTROL)
       .click(el1)
       .click(el2)
       .click(el3)
       .keyUp(Keys.CONTROL).perform();

// ── Shift+Click range select ──
actions.click(firstEl)
       .keyDown(Keys.SHIFT)
       .click(lastEl)
       .keyUp(Keys.SHIFT).perform();

// ── Chain actions ──
actions.moveToElement(menu)
       .click()
       .pause(Duration.ofMillis(300))
       .moveToElement(subItem)
       .click().perform();

// ── Scroll to element (Selenium 4) ──
actions.scrollToElement(element).perform();

// ── Scroll by pixels ──
actions.scrollByAmount(0, 500).perform(); // down 500px
⚙️ JavaScriptExecutor Escape hatch — use when Selenium's built-in methods fail or can't reach the element
Common JS Executor OperationsJSE
Cast driver to JavascriptExecutor. Use JS click when normal click() fails (element hidden behind overlay). Use scrollIntoView when element is off-screen. Use to force-set values on read-only or date-picker inputs.
JavascriptExecutor js =
    (JavascriptExecutor) driver;

// ── Scroll element into view ──
js.executeScript("arguments[0].scrollIntoView(true);", el);
// Center it on screen:
js.executeScript(
    "arguments[0].scrollIntoView({block:'center'});", el);

// ── Click via JS (when normal click fails) ──
js.executeScript("arguments[0].click();", el);

// ── Force set value (date pickers, readonly) ──
js.executeScript(
    "arguments[0].value='2024-12-31';", dateInput);

// ── Remove readonly / disabled ──
js.executeScript(
    "arguments[0].removeAttribute('readonly');", el);
js.executeScript(
    "arguments[0].removeAttribute('disabled');", el);

// ── Scroll page ──
js.executeScript("window.scrollTo(0,0);");            // top
js.executeScript(
    "window.scrollTo(0,document.body.scrollHeight);"); // bottom
js.executeScript("window.scrollBy(0,300);");          // by px

// ── Get return value ──
String title = (String) js.executeScript(
    "return document.title;");
Long scrollY = (Long) js.executeScript(
    "return window.scrollY;");

// ── Highlight element (debug only) ──
js.executeScript(
    "arguments[0].style.border='3px solid red';", el);
When to Use JS vs Normal APIdecision guide
JS Executor is a workaround — use it only when needed, not as the default.
✅ Use JS when
el is covered by overlay el is hidden / off-screen date picker won't accept sendKeys field is readonly/disabled need to scroll to exact px need browser-internal data (title, scrollY, etc.)
❌ Don't use JS when
normal click() works fine sendKeys() works fine element is just not waited for (use proper waits instead) overusing JS hides real bugs in your test
📋 Dropdowns — Select Class Only for HTML <select> elements — not custom div/ul dropdowns
Select — All MethodsSelect
Wrap the <select> WebElement in a Select object. Identify which method to use: visible text (label shown), value (HTML value attribute), or index (position, 0-based).
WebElement dd = driver.findElement(
    By.id("country"));
Select sel = new Select(dd);

// ── Select ──
sel.selectByVisibleText("India");  // text shown
sel.selectByValue("IN");         // value attr
sel.selectByIndex(2);             // 0-based index

// ── Get selected ──
String selected = sel.getFirstSelectedOption().getText();
List<WebElement> all = sel.getAllSelectedOptions();

// ── Get all options ──
List<WebElement> opts = sel.getOptions();
for (WebElement o : opts)
    System.out.println(o.getText());

// ── Multi-select ──
boolean multi = sel.isMultiple();
sel.selectByVisibleText("Java");
sel.selectByVisibleText("Python");
sel.deselectByVisibleText("Java");
sel.deselectAll();
Custom Dropdown (div/ul based)non-select
Most modern UIs use custom dropdowns (not <select>). The Select class won't work. Click to open, then find and click the option.
// Custom dropdown — e.g. Bootstrap, Material UI
// Step 1: Click to open the dropdown
driver.findElement(By.id("countryDropdown")).click();

// Step 2: Wait for options to appear
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(5));
wait.until(ExpectedConditions
    .visibilityOfElementLocated(
        By.cssSelector(".dropdown-menu")));

// Step 3: Click the option by text
driver.findElement(By.xpath(
    "//li[text()='India']")).click();
📁 File Upload When a test needs to upload a file via <input type="file">
File Upload — sendKeys Approach✅ preferred
For <input type="file"> elements, don't click and use OS dialog (Selenium can't interact with OS dialogs). Use sendKeys() with the absolute file path — Selenium handles the upload dialog internally.
// Get absolute path to file
String filePath = System.getProperty("user.dir")
    + "/src/test/resources/testfile.pdf";

// Find the file input (may be hidden)
WebElement fileInput = driver.findElement(
    By.cssSelector("input[type='file']"));

// Send the file path directly
fileInput.sendKeys(filePath);

// If input is display:none, make visible first
((JavascriptExecutor) driver).executeScript(
    "arguments[0].style.display='block';", fileInput);
fileInput.sendKeys(filePath);
File Download — Folder ConfigChromeOptions
To control where Chrome saves downloaded files and prevent the download dialog, set the prefs in ChromeOptions before starting the driver.
Map<String, Object> prefs = new HashMap<>();
prefs.put("download.default_directory",
    "/path/to/downloads");
prefs.put("download.prompt_for_download", false);
prefs.put("plugins.always_open_pdf_externally", true);

ChromeOptions opts = new ChromeOptions();
opts.setExperimentalOption("prefs", prefs);
WebDriver driver = new ChromeDriver(opts);

📸 Screenshots Capture on test failure to see what went wrong at that moment
Full Page & Element ScreenshotTakesScreenshot
Capture on test failure in @AfterMethod using ITestResult. Element-level screenshot (Selenium 4) is great for capturing just a chart or specific UI region.
// ── Full page screenshot ──
File src = ((TakesScreenshot) driver)
    .getScreenshotAs(OutputType.FILE);
FileUtils.copyFile(src,
    new File("screenshots/test_" +
        System.currentTimeMillis() + ".png"));

// ── Element-only screenshot (Selenium 4) ──
WebElement chart = driver.findElement(
    By.id("revenueChart"));
File elFile = chart.getScreenshotAs(OutputType.FILE);
FileUtils.copyFile(elFile,
    new File("screenshots/chart.png"));

// ── As byte array (for Allure/ExtentReports) ──
byte[] bytes = ((TakesScreenshot) driver)
    .getScreenshotAs(OutputType.BYTES);
Auto-Screenshot on Failurepattern
Put this in @AfterMethod so every failed test saves a screenshot automatically.
@AfterMethod
public void tearDown(ITestResult result) {
    if (result.getStatus() ==
            ITestResult.FAILURE) {
        File src = ((TakesScreenshot) driver)
            .getScreenshotAs(OutputType.FILE);
        String name = result.getName()
            + "_" + System.currentTimeMillis();
        FileUtils.copyFile(src,
            new File("screenshots/"+name+".png"));
    }
    driver.quit();
}
🧪 TestNG — Complete Guide Every annotation, attribute, assertion, listener, and parallel trick you need
Annotation Lifecycle — Execution OrderTestNG
Memorize this order. @BeforeMethod / @AfterMethod wrap every single @Test. @BeforeClass runs once per class. Mix them wrong and your driver won't exist when your test runs.
1
@BeforeSuiteRuns once before everything. Use for: starting test servers, DB seeds, global report setup.
2
@BeforeTestBefore every <test> tag in testng.xml. Use for: browser profile selection per test group.
3
@BeforeClassOnce before all @Test methods in this class. Use for: one-time page navigation, shared login.
4
@BeforeMethod← Driver init goes hereBefore every @Test. Launch browser, navigate to base URL.
T
@TestThe actual test method. Should only contain test logic + assertions.
5

Hard Assertions — Assert.*stops on fail
Use for critical checks where failing means there's no point running the rest of the test. Test stops immediately at the first failed assertion.
// ── Equality ──
Assert.assertEquals(actual, expected);
Assert.assertEquals(actual, expected, "Failure message");
Assert.assertNotEquals(actual, notExpected);

// ── Boolean ──
Assert.assertTrue(condition);
Assert.assertTrue(condition, "Should be true because...");
Assert.assertFalse(condition);

// ── Null checks ──
Assert.assertNull(obj);
Assert.assertNotNull(obj);
Assert.assertNotNull(obj, "Object must not be null");

// ── Same object reference ──
Assert.assertSame(obj1, obj2);     // same reference
Assert.assertNotSame(obj1, obj2);  // different reference

// ── Arrays / Collections ──
Assert.assertEquals(actualArr, expectedArr);
Assert.assertEquals(actualList, expectedList);

// ── Fail manually ──
Assert.fail("This should never be reached");

// ── Common patterns ──
Assert.assertEquals(driver.getTitle(), "Dashboard");
Assert.assertTrue(driver.getCurrentUrl().contains("home"));
Assert.assertTrue(element.isDisplayed(), "Button must be visible");
Assert.assertEquals(element.getText().trim(), "Submit");
Soft Assertions — SoftAssertcollects all failures
Use when you want to verify multiple things on a page and see ALL failures at once — e.g., checking every field on a form, or every item in a list. Must call assertAll() at the end.
// Create ONE SoftAssert per test method
SoftAssert soft = new SoftAssert();

// ── Make multiple checks — none stop the test ──
soft.assertEquals(driver.getTitle(), "Dashboard");
soft.assertTrue(header.isDisplayed(), "Header visible");
soft.assertFalse(errorBanner.isDisplayed(), "No error");
soft.assertEquals(userGreeting.getText(), "Hi, John");
soft.assertNotNull(profileImg.getAttribute("src"));
soft.assertTrue(driver.getCurrentUrl().contains("dashboard"));

// ── CRITICAL: MUST call this at end ──
// Throws AssertionError with ALL failures listed
soft.assertAll();

// ── Common mistake to avoid ──
// DO NOT share SoftAssert between test methods!
// Create new SoftAssert() inside each @Test.
⚠️
If you forget soft.assertAll() — the test always passes even when assertions fail. Never skip it.

ThreadLocal Driver — Safe Parallel Testsparallel safe
When parallel=methods or parallel=classes, each thread needs its OWN WebDriver. ThreadLocal gives each thread a separate driver instance automatically.
public class DriverManager {
    private static final ThreadLocal<WebDriver>
        driverTL = new ThreadLocal<>();

    public static void init(String browser) {
        WebDriver d;
        if (browser.equals("firefox")) {
            WebDriverManager.firefoxdriver().setup();
            d = new FirefoxDriver();
        } else {
            WebDriverManager.chromedriver().setup();
            d = new ChromeDriver();
        }
        driverTL.set(d);
    }

    public static WebDriver getDriver() {
        return driverTL.get();
    }

    public static void quit() {
        driverTL.get().quit();
        driverTL.remove(); // prevent memory leak!
    }
}

Implement ITestListener to hook into test events — auto-screenshot on failure, custom logging, report integration (Allure, ExtentReports). Register in testng.xml or via @Listeners annotation.
public class TestListener implements ITestListener {

    @Override
    public void onTestStart(ITestResult r) {
        System.out.println("▶ START: " + r.getName());
    }

    @Override
    public void onTestSuccess(ITestResult r) {
        System.out.println("✅ PASS: " + r.getName());
    }

    @Override
    public void onTestFailure(ITestResult r) {
        System.out.println("❌ FAIL: " + r.getName());
        // Auto screenshot on any failure
        WebDriver driver = DriverManager.getDriver();
        if (driver != null) {
            try {
                File f = ((TakesScreenshot) driver)
                    .getScreenshotAs(OutputType.FILE);
                FileUtils.copyFile(f, new File(
                    "screenshots/" + r.getName() + ".png"));
            } catch (Exception e) { e.printStackTrace(); }
        }
    }

    @Override
    public void onTestSkipped(ITestResult r) {
        System.out.println("⏭ SKIP: " + r.getName());
    }

    @Override
    public void onFinish(ITestContext ctx) {
        System.out.println("Suite done. Passed: "
            + ctx.getPassedTests().size()
            + " Failed: "
            + ctx.getFailedTests().size());
    }
    // Also available: onStart, onTestFailedButWithinSuccessPercentage
}

IRetryAnalyzer — Auto-Retry Flaky Testsretry
Use to automatically re-run a failed test up to N times before marking it as failed. Useful for flaky tests caused by network delays or animation timing issues.
// ── Step 1: Implement IRetryAnalyzer ──
public class RetryAnalyzer implements IRetryAnalyzer {
    private int count = 0;
    private static final int MAX_RETRY = 2;

    @Override
    public boolean retry(ITestResult result) {
        if (count < MAX_RETRY) {
            count++;
            System.out.println("Retrying [" + count + "] "
                + result.getName());
            return true;  // retry
        }
        return false;  // give up, mark FAILED
    }
}

// ── Step 2: Attach to @Test ──
@Test(retryAnalyzer = RetryAnalyzer.class)
public void testFlaky() { ... }

public class RetryListener
    implements IAnnotationTransformer {
    @Override
    public void transform(ITestAnnotation ann,
        Class cls, Constructor c, Method m) {
        ann.setRetryAnalyzer(RetryAnalyzer.class);
    }
}

BasePage.java — Shared Helpersbase
All page classes extend BasePage. Put every reusable helper here — click with wait, type with clear, getText, isVisible, scrollTo. Never duplicate these in individual page classes.
public class BasePage {
    protected WebDriver       driver;
    protected WebDriverWait   wait;
    protected JavascriptExecutor js;
    protected Actions         actions;

    public BasePage(WebDriver driver) {
        this.driver  = driver;
        this.wait    = new WebDriverWait(driver,
            Duration.ofSeconds(15));
        this.js      = (JavascriptExecutor) driver;
        this.actions = new Actions(driver);
        PageFactory.initElements(driver, this);
    }

    // ── Wait helpers ──
    protected WebElement waitVisible(By by) {
        return wait.until(ExpectedConditions
            .visibilityOfElementLocated(by));
    }
    protected WebElement waitClickable(By by) {
        return wait.until(ExpectedConditions
            .elementToBeClickable(by));
    }
    protected void waitForUrl(String partial) {
        wait.until(ExpectedConditions
            .urlContains(partial));
    }

    // ── Action helpers ──
    protected void click(By by) {
        waitClickable(by).click();
    }
    protected void type(By by, String text) {
        WebElement el = waitVisible(by);
        el.clear();
        el.sendKeys(text);
    }
    protected String getText(By by) {
        return waitVisible(by).getText().trim();
    }
    protected boolean isVisible(By by) {
        try {
            return driver.findElement(by).isDisplayed();
        } catch (NoSuchElementException e) {
            return false;
        }
    }
    protected void scrollTo(By by) {
        js.executeScript(
            "arguments[0].scrollIntoView({block:'center'});",
            driver.findElement(by));
    }
    protected void hover(By by) {
        actions.moveToElement(driver.findElement(by))
               .perform();
    }
    protected String getUrl() {
        return driver.getCurrentUrl();
    }
    protected String getTitle() {
        return driver.getTitle();
    }
}

BaseTest.java — Full Production Versionbase test
Every test class extends this. It handles driver creation, teardown, screenshot on failure, and browser selection from config. Tests only write @Test methods.
public class BaseTest {

    protected WebDriver driver;
    private String browser = ConfigReader.get("browser");
    private String baseUrl  = ConfigReader.get("baseUrl");

    @BeforeMethod
    public void setUp(Method method) {
        System.out.println("\n▶ Running: " + method.getName());
        driver = createDriver(browser);
        driver.manage().window().maximize();
        driver.manage().timeouts()
            .pageLoadTimeout(Duration.ofSeconds(30));
        driver.get(baseUrl);
    }

    private WebDriver createDriver(String browser) {
        switch (browser.toLowerCase()) {
            case "firefox":
                WebDriverManager.firefoxdriver().setup();
                return new FirefoxDriver();
            case "edge":
                WebDriverManager.edgedriver().setup();
                return new EdgeDriver();
            default:
                WebDriverManager.chromedriver().setup();
                return new ChromeDriver();
        }
    }

    @AfterMethod
    public void tearDown(ITestResult result, Method method) {
        if (result.getStatus() == ITestResult.FAILURE) {
            captureScreenshot(method.getName());
        }
        if (driver != null) driver.quit();
    }

    private void captureScreenshot(String testName) {
        try {
            File src = ((TakesScreenshot) driver)
                .getScreenshotAs(OutputType.FILE);
            String path = "screenshots/"
                + testName + "_"
                + System.currentTimeMillis() + ".png";
            FileUtils.copyFile(src, new File(path));
            System.out.println("Screenshot: " + path);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

public class ConfigReader {
    private static Properties props;

    static {
        try {
            props = new Properties();
            FileInputStream fis = new FileInputStream(
                "src/main/resources/config.properties");
            props.load(fis);
        } catch (IOException e) {
            throw new RuntimeException(
                "config.properties not found", e);
        }
    }

    public static String get(String key) {
        return props.getProperty(key);
    }

    public static int getInt(String key) {
        return Integer.parseInt(get(key));
    }
}

            String email, String pass, String expectedErr) {
        loginPage.loginExpectingFailure(email, pass);
        SoftAssert soft = new SoftAssert();
        soft.assertTrue(loginPage.isErrorDisplayed());
        soft.assertEquals(loginPage.getErrorMessage(), expectedErr);
        soft.assertAll();
    }

    @DataProvider(name = "invalidLogins")
    public Object[][] invalidLoginData() {
        return new Object[][] {
            {"",           "",      "Email is required"},
            {"notanemail", "pass", "Enter a valid email"},
            {"x@x.com",    "",      "Password is required"}
        };
    }
}
POM Anti-Patterns — What NOT To Doavoid
These are the most common POM mistakes. Recognising and fixing them makes your framework maintainable.
❌ Wrong — Breaks POM
// Locator in test class
@Test
void test() {
  driver.findElement(
    By.id("email"))
    .sendKeys("x");
}

// Assert in page class
public void login() {
  loginBtn.click();
  Assert.assertTrue(
    homePage.isDisplayed());
}

// driver.quit() in page
public void logout() {
  logoutBtn.click();
  driver.quit();
}

// Hardcoded URL in test
driver.get(
  "http://localhost:8080");
✅ Right — Follows POM
// Only page objects in tests
@Test
void test() {
  loginPage.typeEmail("x");
}

// Page returns next page
public HomePage login() {
  loginBtn.click();
  return new HomePage(driver);
  // test will assert
}

// Teardown in BaseTest
@AfterMethod
public void tearDown() {
  driver.quit();
}

// URL from config
driver.get(
  ConfigReader.get("baseUrl"));
🐛 Common Exceptions & How to Fix Them What to do when your test fails with one of these
ExceptionWhy It HappensHow to Fix
NoSuchElementException Element not in DOM yet, wrong locator, inside an iframe Add ExplicitWait (presenceOfElementLocated); verify locator in DevTools; check if element is in an iframe and switch first
ElementNotInteractableException Element in DOM but not visible or behind another element Wait for visibilityOf; scrollIntoView via JS; wait for overlay/modal to close
StaleElementReferenceException Page re-rendered after you found the element — reference is now dead Re-find element after any page action. For loops, use the By locator and re-find each iteration
ElementClickInterceptedException Something (modal, cookie banner, sticky header) is covering the element Close the overlay first; scrollIntoView; use JS click as last resort
TimeoutException ExpectedCondition not met before timeout expired Increase timeout; verify the condition itself (correct locator? right condition type?); check page is actually loading
NoAlertPresentException Tried to switch to alert before it appeared Use wait.until(ExpectedConditions.alertIsPresent()) before switchTo().alert()
NoSuchWindowException Tried to switch to a window handle that no longer exists Re-fetch getWindowHandles(); don't store handles across page navigations
NoSuchFrameException Frame name/id is wrong or frame not loaded yet Use frameToBeAvailableAndSwitchToIt(); verify frame name in page source
InvalidSelectorException CSS or XPath syntax is wrong Test your selector in browser DevTools console: $("css") or $x("xpath")
SessionNotCreatedException ChromeDriver version doesn't match Chrome browser version Use WebDriverManager — it auto-matches versions
MoveTargetOutOfBoundsException Actions.moveToElement target is not in viewport Scroll element into view first using JS or actions.scrollToElement()
